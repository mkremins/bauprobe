# Bauprobe
A demonstration of how the [Praxish](https://github.com/mkremins/praxish) social simulation framework can be used to drive character behavior in a graphical game with continuous time and space.

## Implementation notes

Praxish actions drive character movements and animations by inserting *DM instructions* into the database. These are just plain old exclusion logic sentences, currently of the form `dm.Char.InstructionType.Args`, that the DM (drama manager) interprets as character-specific performance directives. Every time a character performs a Praxish action, we query the database to see if any new DM instructions were inserted under the `dm` prefix, and execute any instructions we find; executing a `planPath` instruction, for instance, involves telling a character to move along a DM-planned path to a particular room, while executing a `markBusy` instruction instead tells them to pause and display a particular emoji for a particular duration of time. After all the DM instructions are processed, we delete the whole `dm` subtree from the database, effectively clearing out the DM’s “inbox”.

As characters move about the map executing their assigned tasks, the DM keeps track of their locations and whether they’re currently busy or not, updating the Praxish DB to reflect updated character status information whenever there’s a significant change. Additionally, whenever a character finishes up all their queued movements and animations, the DM asks Praxish to generate a list of actions that the character is currently allowed to perform, then uses a weighted random procedure (based on each action’s associated [sways](https://github.com/mkremins/praxish/blob/master/swaygent.js)) to decide what action the character should undertake next. Performing the selected action generally causes the insertion of DM instructions that fill up the character’s task queue again, and the loop repeats.

Overall, Praxish ends up guiding all the character *decision-making* about what to do next. The spatiotemporal *execution* of decisions is handled by a relatively simple DM whose primary responsibility is to keep each character moving through a queue of Praxish-assigned tasks.
